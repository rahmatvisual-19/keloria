# Skenario User Acceptance Testing (UAT) — Kelo-ERP

Daftar skenario uji penerimaan yang memetakan langsung seluruh 11 Kriteria Penerimaan Kelo-ERP.

| ID | Kriteria | Skenario | Langkah Pengujian | Hasil Diharapkan |
|---|---|---|---|---|
| **UAT-01** | Alur B2B & Invoice DP Otomatis | Input PO B2B menerbitkan Invoice DP 50% otomatis | Login sebagai `pegawai` → buka **Sales → Pesanan** → klik **Buat Pesanan Baru** → pilih `PO Besar`, pelanggan B2B, 20 pack `KLR-004` → klik **Simpan**. | Order `ORD-YYYYMM-XXXX` tersimpan (status `Menunggu_Pembayaran`), pratinjau DP 50% tampil, dan Invoice `DP_50` terbit otomatis di Finance tanpa input ulang. |
| **UAT-02** | Kemudahan Staf Baru & Validasi Form | Anak PKL input PO mandiri mengikuti panduan | Login sebagai `pkl` → baca halaman `/panduan` → coba simpan form order dengan penerima kosong atau qty 0 → lengkapi data valid lalu simpan. | Data tidak valid ditolak dengan pesan inline Bahasa Indonesia; data valid berhasil tersimpan. |
| **UAT-03** | Verifikasi DP → BOM & Produksi | Verifikasi DP membuka BOM & transisi berurutan | Verifikasi Invoice DP 50% sebagai `pegawai` → cek status order → buka **SCM → Kalkulator BOM** → coba lompat status `DP_Lunas → Packing` → majukan tahap berurutan. | Order pindah ke `DP_Lunas`, BOM menghitung `Σ(qty × qty_per_unit)`, lompat tahap ditolak (400), transisi berurutan tercatat di `order_status_logs`. |
| **UAT-04** | Guard Pengiriman Sebelum Pelunasan | Blokir `Dikirim` bila Invoice Pelunasan belum Lunas | Majukan order B2B ke `Siap_Kirim` dengan ongkir → coba ubah langsung ke `Dikirim` → verifikasi Invoice Pelunasan di Finance → ubah ke `Dikirim`. | Percobaan pertama ditolak dengan pesan *"Pelunasan belum terverifikasi"*. Setelah pelunasan `Lunas`, status `Dikirim` berhasil disimpan. |
| **UAT-05** | Alur B2C & Stok Atomik | Order B2C mengurangi stok online & memicu Alert Stock | Catat order `Online` B2C melebihi stok tersedia → ulangi dengan qty valid hingga stok ≤ batas minimum → cek sidebar & banner dasbor. | Order melebihi stok ditolak (409, tanpa stok minus); order valid memotong stok atomik & memunculkan **Alert Stock** di sidebar, dasbor, dan SCM. |
| **UAT-06** | Pembatalan B2C Kembalikan Stok | Membatalkan order B2C sebelum `Dikirim` mengembalikan stok | Batalkan order B2C berstatus `Packing` lewat `POST /api/v1/sales/orders/:id/cancel` → cek `stock_online` produk. | Status menjadi `Dibatalkan` dan `stock_online` bertambah kembali sebesar `qty` order. |
| **UAT-07** | Laporan Keuangan Bulanan & Ekspor | Owner melihat & mengunduh laporan PDF dan Excel | Login sebagai `owner` → buka **Finance → Laporan Bulanan** atau `GET /api/v1/reports/financial?month=2026-11&format=pdf\|excel`. | Menampilkan `kas_masuk`, `kas_keluar` (biaya + payroll), `piutang`, `laba_rugi_bersih`; file PDF dan `.xlsx` terunduh valid. |
| **UAT-08** | Dasbor B2B vs B2C | Owner melihat grafik perbandingan omzet bulanan | Login sebagai `owner` → buka `/` dan `/sales` tab **Dasbor Penjualan**. | Kartu ringkasan dan grafik batang omzet B2B vs B2C per bulan tampil lengkap. |
| **UAT-09** | Matriks RBAC 4 Role & Akun Nonaktif | Uji isolasi akses `Owner`, `Manager/SDM`, `Pegawai`, `Anak PKL`, dan `Nonaktif` | Uji akses masing-masing role ke `/api/v1/users`, `/api/v1/hr/employees`, `/api/v1/hr/payrolls`, `/api/v1/sales/dashboard`, `/api/v1/reports/financial`, dan `/api/v1/finance/invoices/:id/verify`; nonaktifkan akun yang sedang login. | `Manager/SDM` 403 di Owner-only & tidak melihat `base_salary`; `Pegawai` 403 di seluruh HR; `Anak PKL` 403 di verifikasi bayar & HR; akun `Nonaktif` langsung 401 di sesi berjalan. |
| **UAT-10** | Keamanan Password & Upload Bukti Bayar | Password ter-hash & file ilegal/oversize ditolak | Cek tabel `users` & respons `/auth/me`, `/users`, `/hr/employees`; unggah file `.exe` dan file `.png` > 2 MB ke endpoint verifikasi pembayaran. | `password_hash` tersimpan bcrypt dan tidak pernah muncul di API; file `.exe` dan > 2 MB ditolak dengan 400. |
| **UAT-11** | PO Supplier Otomatis Catat Biaya | Status PO `Diterima` membuat 1 biaya supplier idempoten | Buat PO supplier → ubah status ke `Diterima` → cek tabel `expenses` → ubah status ke `Selesai`. | Tepat 1 baris `expenses` kategori `Pembelian Supplier` terbuat otomatis (tidak duplikat). |
